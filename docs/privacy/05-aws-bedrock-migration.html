Every AI call this product makes today leaves for api.openai.com (and one for api.x.ai). How this relates to pages 03 and 04

Page 03 recommended Azure OpenAI and set Bedrock aside because it offered "Claude and others, not OpenAI — you would re-tune every prompt". The migration plan's September 2026 verification of AWS documentation records that OpenAI's GPT-5.6 Luna / Terra / Sol are now served on Bedrock through an OpenAI-compatible /openai/v1/chat/completions endpoint. That removes 03's main objection, so the decision moved to AWS. Page 04's gateway-and-aliasing phases are not what this plan does; it replaces the 83 hand-written fetches with one shared client inside the existing server. Aliasing (page 02) stays an optional layer that could later live inside that client. Where 03/04 and this page disagree, this page is current.

Summary

The one-paragraph version

The backend on Render (server/) contains 90 provider call sites: 83 chat completions, 4 image generations, 2 speech-to-text, 1 video. They are all hand-written fetch() blocks; there is no SDK and no shared client. The plan introduces one shared AI client that resolves URL, key and model from an AI_PROVIDER environment variable, migrates every chat site onto it (same request shape, so the refactor merges with zero behaviour change while AI_PROVIDER=openai), adds small AWS-SDK clients for images and speech, and then flips the variable to bedrock on the Render service. Rollback is flipping it back.

Is this a major refactor?

Wide but shallow. By file count it is large (~65 files touched); by conceptual weight it is a consolidation: 83 copies of the same 30-line pattern collapse into a 5-line call. No domain logic, schema or UI changes. The real risk is model behaviour drift (prompts tuned on gpt-4o-mini / gpt-5.2 running on GPT-5.6), which is why the plan spends as much effort on smoke checks and a staging comparison run as on code. Rough effort: one to two weeks of code, plus one to two weeks around it for AWS account setup, a duplicate staging stack and the comparison run.

Why

The sentence we want to be able to sign

Corporate clients run crisis-team training here. Their scenario briefs, uploaded documents, participant messages, public statements and voice input all pass through model calls. The goal is a contractual statement that is simply true.

Today — what is true
Prompts and completions are sent to OpenAI's public API (and xAI for video) under our API keys, subject to those providers' data-use terms.
  • Provider terms govern retention and abuse review.
  • Two third parties on the wire (OpenAI, xAI).
  • No account-level "zero retention" switch we control.
After cutover — what becomes true
Model inference is performed via Amazon Bedrock and Amazon Transcribe within our AWS account. Inputs and outputs are not shared with model providers and are not used to train foundation models. Bedrock is configured for zero data retention, enforced by organisation policy.
  • Bedrock is AWS-hosted inference inside the AWS trust boundary, like S3 or RDS.
  • Model providers have no access to the deployment, logs, prompts or completions.
  • data_retention_mode: none, locked by an SCP; org-wide AI opt-out for Transcribe.
Why Bedrock specifically, and why not the alternatives

Same models, same wire format. GPT-5.6 on Bedrock is reached through an OpenAI-compatible chat-completions endpoint, so the 83 request bodies survive nearly unchanged and the prompts keep working. Not self-hosting: evaluated and deferred — feasible (vLLM speaks the same wire format, so this abstraction still applies) but it costs GPU hardware, a quality gap on long multi-constraint prompts, and owning inference ops. Not a gateway: the Render server already holds the provider key; adding a hop adds latency and a component without changing what the provider sees.

function resolve(tier: AiTier) {
  if (env.aiProvider === 'bedrock') {
    return {
      url:   `${env.aiBaseUrl}/chat/completions`,
      key:   env.aiApiKey,
      model: env.aiModel[tier],          // luna / terra from env
    };
  }
  return {                             // byte-identical to today
    url:   'https://api.openai.com/v1/chat/completions',
    key:   env.openAiApiKey,
    model: { fast: 'gpt-4o-mini', standard: 'gpt-5.2',
             vision: 'gpt-5.1', search: 'gpt-4o-search-preview' }[tier],
  };
}

Every feature that can call a model first checks for the OpenAI key. That check has to become provider-agnostic, or removing OPENAI_API_KEY after cutover silently switches off the chat surveillance worker, the statement watchdog, the pressure engine, the bots and dozens of smaller features.

Risks & evidence

What the audit found that the first plan did not

Each card says what could go wrong, where the evidence is in the code, and what the plan does about it. "Proven" means it has already happened in this codebase; "verify" means a smoke check decides; "design" means the client is built to absorb it.

Newer models reject temperatureproven

~70 request bodies send a non-default temperature. If the target model returns 400, callers silently fall back to null or a default result — nothing crashes, quality just quietly dies.

commit 44e26d7 · contentGraderService.ts: removed temperature: 0.3 — "gpt-5.5 rejects any temperature other than the default and returns a 400, which lands every response on the neutral defaultGrade".
AI_TEMPERATURE_POLICY=auto strips it per model and logs once; smoke check 3 decides for GPT-5.6.
Tiny completion budgets vs reasoning tokensverify

Eight fast-tier sites cap output at 30–150 tokens. If GPT-5.6 spends reasoning tokens inside max_completion_tokens, those return empty or truncated JSON.

insiderService.ts L220 (30) · incidentDecisionGradingService.ts L98, L156 (50) · decisionEvaluationAiService.ts L120 (120), L61, L179 (150) · aiService.ts L1577 (150) · hospitalCapacityService.ts L68 (150)
Smoke check 4 with a 30-token request; AI_FAST_MIN_COMPLETION_TOKENS or a no-reasoning setting under Bedrock.
Vision images are remote URLsverify

All five vision sites pass Supabase Storage HTTPS URLs; none inline base64. Bedrock's OpenAI-compatible path may not fetch external URLs the way OpenAI does.

rtsSceneEnrichmentService.ts L244, L389, L951 (detail: 'high') · rtsVisionService.ts L52 · rtsCasualtyService.ts L219
Smoke check 2 uses a real remote URL; the client downloads and inlines a data: URL if needed.
Strict json_schema is now in useverify

The AI teammate bots request strict structured output and already carry a fallback to json_object with the schema inlined. Bedrock support for strict mode is unverified.

teammates/llmQueue.ts L142-145 (json_schema, strict) · L150-161 (fallback) · schemas in teammates/brain.ts
Smoke check 5; the client ports the fallback verbatim and can skip straight to it under Bedrock.
Browser audio format vs Transcribe streamingdesign

The recorder produces WebM/Opus. Transcribe streaming accepts only PCM, OGG-Opus or FLAC; batch accepts WebM but needs S3 and an async job.

frontend/src/hooks/useVoiceInput.ts L35-37 · routes/ai.ts L88-113 (raw body, 10 MB) · routes/voice.ts L113-157 (batch over storage)
Batch for both sites first; measure live latency on staging; streaming only with a demux or recorder change.
Six workers call models on timersdesign

The engine ticker runs every 60 s for every live social session and is ON by default in production; bots add up to 400 calls per session per hour. Bedrock enforces per-model RPM/TPM quotas.

server/index.ts L73-94 · engineTicker.ts L17, L26 (ENABLE_EXECUTIVE_DECISIONS default on) · teammateBotService.ts L29, L81 · env.ts L100
Size quotas from a realistic staging session (check 13); optional serialize for ticker callers; never point two backends at one database.
The Vercel bridge mounts AI routesverify

api/index.ts mounts scenarios, sessions, decisions, AAR and the Whisper route and imports env.ts. It is dormant only if the frontend points at Render.

api/index.ts L12, L72-81 · frontend/src/lib/api.ts L9 (VITE_API_URL || '') · vercel.json has no /api rewrite
Confirm VITE_API_URL; never set AI_PROVIDER=bedrock on Vercel; optionally drop the AI routers from the bridge.
~91 key gates, ~499 threaded parametersdesign

Removing the OpenAI key after cutover would silently disable every feature still gated on it. The openAiApiKey parameter is threaded through 67 files.

warroomAiService.ts (100 occurrences) · aiService.ts (35) · warroomService.ts, warroomResearchService.ts (26 each) · decisionEvaluationOrchestrator.ts (25) · routes/warroom.ts (21)

Smoke checks

Eight requests before touching 83 sites

Each is one request against Bedrock from a scratch script. Together they settle every open technical question in the client's design before the migration pass starts.

  1. Chat completion with response_format: { type: 'json_object' } returns valid JSON on Luna and Terra.Decision 4: json_object stays.
  2. Vision request with a remote HTTPS image_url (a real Supabase Storage object), with and without detail: 'high', succeeds on Terra.Fails → client inlines base64.
  3. temperature: 0.2 and 0.85 accepted on Luna and Terra.Expect rejection given gpt-5.5's behaviour; auto policy strips it.
  4. Fast-tier JSON request with max_completion_tokens: 30 (the insider prompt) returns usable content on Luna.Fails → no-reasoning setting or AI_FAST_MIN_COMPLETION_TOKENS.
  5. Strict json_schema (one of the bots' schemas) honoured on Luna and Terra.Fails → go straight to the json_object + inlined-schema fallback.
  6. max_tokens rejected or ignored; max_completion_tokens accepted.Confirms the ceiling normalisation is required.
  7. Model IDs resolve in the chosen region; IAM identity has bedrock:InvokeModel on the inference profile and the default project; note RPM/TPM quotas.Also the first real cost datapoint.
  8. A deliberate 4xx/429 carries an HTTP status the retry logic keys on.The client retries on status, not on OpenAI's error body.

Glossary

Terms used above

Amazon Bedrock
AWS's managed inference service. Multi-tenant, but inside the AWS trust boundary like S3 or RDS; model providers cannot see the deployment, prompts or completions.
OpenAI-compatible endpoint
bedrock-runtime.<region>.amazonaws.com/openai/v1/...: accepts the same chat-completions request body OpenAI does, authenticated with a Bedrock API key as Bearer. Why the 83 sites port cheaply.
Inference profile
Model IDs like us.openai.gpt-5.6-luna: the us. prefix routes within US regions. GPT models are only reachable this way on bedrock-runtime.
bedrock-mantle
A second endpoint offering in-region GPT (us-east-1/2) and the only server-side web_search tool, via the Responses API. Not needed: web search is dropped; the six search sites run as plain chat on the standard tier.
data_retention_mode
Bedrock account/project setting: none (zero retention, our choice), default (AWS may retain for abuse detection), aws_review. Models needing review simply become unavailable under none.
SCP
AWS Organizations Service Control Policy. Used to deny changing the retention mode away from none.
AI services opt-out policy
Organization-wide policy that stops AWS AI services (notably Transcribe) from using content for service improvement. Bedrock does not need it; Transcribe does.
Amazon Transcribe
AWS speech-to-text. Batch jobs read audio from S3 asynchronously and accept WebM; streaming is real-time but accepts only PCM, OGG-Opus or FLAC.
InvokeModel
The native Bedrock API (via the AWS SDK, IAM credentials) used for models without an OpenAI-compatible shape, here Stability image generation.
Tier
What a call site asks for instead of a model name: fast, standard, vision. Env maps each tier to a model per provider. (A search tier was considered and dropped: the six search sites move to standard.)
AI_PROVIDER
The switch. openai reproduces today's requests exactly; bedrock routes to AWS. Flipping it on Render is the cutover; flipping it back is the rollback.
aiEnabled
Derived flag replacing ~91 env.openAiApiKey checks: true when the active provider's key is present.
Shared client
chatClient / imageClient / transcribeClient under server/services/ai/: the only code that knows a provider URL, key or model ID.
